# 0001 采用 Vosk 作为离线中文语音识别

- 状态：已采纳（S0–S1 实现）
- 日期：2026-11-12

## 背景

系统要在手机端离线完成 M0–M5，语音识别不能依赖网络。可选方案有三类：端侧离线模型、云端 API、端侧大模型。课程约束是"断网可用、包体积可控、可复现"。

## 决策

采用 Vosk + 中文模型 `vosk-model-cn-0.22`：

- 手机端依赖 `com.alphacephei:vosk-android:0.3.47`；电脑端用 PyPI `vosk`（当前环境 0.3.45）。
- 模型 `vosk-model-cn-0.22.zip` 为 1,358,736,686 B，解压后 2,043,416,000 B，许可证 Apache-2.0，由 `models/prepare_models.py` 按固定提交下载并登记 22 个运行文件的 SHA256。
- 识别器按 8000 字节块流式送入，输出 `full_text` 与按词时间戳重建的 `segments[]`。

## 后果

- 断网可用，不产生上行流量；代价是安装包与模型占空间，且首次加载需要把模型目录放到应用私有目录。
- 中文识别质量对录音条件敏感。用同一模型对标准普通话合成语音实测，CER 为 0.0；手机远场录音出现过词边界混淆（"居民"→"取名"、"需求"→"寻求"、"评估"→"凭空"），说明瓶颈在录音链路与连读，而非词表覆盖。
- 电脑端 0.3.45 与 Android 端 0.3.47 存在两个小版本的差异，跨端对照时需记录版本号，不能假设两者逐字一致。

## 备选与未采纳理由

| 备选 | 未采纳理由 |
|---|---|
| sherpa-onnx / Paraformer | 中文 CER 通常更低，但模型文件、运行时依赖、Android 集成方式都要重做，且会让已采集的 30 段标注基线作废；留作 S2 基线出来后再评估 |
| 云端 ASR API | 违背"离线可用"约束，且引入网络时延与隐私问题 |
| Whisper 端侧 | 模型体积与手机推理耗时不适合本项目的中低端设备目标 |

## 复核方式

`models/manifest.json` 对 22 个运行文件逐个登记 SHA256；`experiments/scripts/model_probe.py` 可在不加载 UI 的情况下验证模型能否加载与释放。
