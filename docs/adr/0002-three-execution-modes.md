# 0002 执行计划采用 LOCAL / REMOTE / MANUAL_MIXED 三模式

- 状态：已采纳（S1 起实现，S3 使用）
- 日期：2026-11-12

## 背景

S3 要求"同一份片段分别送到手机和电脑的 M2，再扩到 M1、M3、M4"，S4 还要对 16 种模块归属做最小割复算。如果只有一个 `remote: Boolean` 开关，就只能表达"全本地 / 全远程"，无法表达"M1 在手机、M2 在电脑"这类中间状态，S3 的对照与 S4 的枚举都会缺一个维度。

## 决策

`Execution.kt` 定义 `PlanMode { LOCAL, REMOTE, MANUAL_MIXED }`，并由 `ExecutionPlan` 在构造时强制校验：

| 模式 | 约束 |
|---|---|
| `LOCAL` | `remote` 必须为空 |
| `REMOTE` | `remote` 必须等于可远程集合 `{M1, M2, M3, M4}` |
| `MANUAL_MIXED` | `remote` 非空，且不等于全集（至少一端本地、至少一端远程） |

`M0`（采集）与 `M5`（反馈）固定本地，不参与远程集合；这与实施计划的"M0/M5 固定本地"一致。

## 后果

- 计划本身就是可校验的数据结构，非法组合在构造期抛出，不会等到运行到某一模块才失败。
- 每个模块的归属可由 `executor(module)` 直接读出，S3 的"归属记录"和 S4 的"16 种枚举"共用同一份模型，不需要另写一套映射。
- 代价是多了一个必须维护的 `eligible` 集合：将来若允许 M0/M5 远程，需要同时改校验与契约。

## 备选与未采纳理由

| 备选 | 未采纳理由 |
|---|---|
| 单个 `remote: Boolean` | 只能表达全本地/全远程，S3 的逐模块对照与 S4 的部分切分都表达不了 |
| 每个模块一个开关（6 个布尔） | 组合空间大且缺少语义约束，容易构造出"M0 远程、M5 本地"这类契约上不允许的计划 |
| 用 JSON 配置文件驱动 | 运行时才报错，且校验逻辑会散落在加载代码里，不利于单测 |

## 复核方式

`contracts/execution-plan.schema.json` 定义外部形态；`contracts/examples/ljx-execution-plans.json` 提供三模式样例；手机端构造 `ExecutionPlan` 时的 `require` 即校验点。
