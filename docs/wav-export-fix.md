# APK 0.2.1：恢复已保存 WAV 的导出

手机实际录音链路成功后，用户反馈“导出最近 WAV”提示没有音频，但事件日志可导出。检查发现旧版导出入口只认 Activity 的 latestAudio 内存字段；应用切换/重建后该字段清空，已存在的 app-private last.wav 没有被用于导出。文件选择器返回时同样可能遇到字段丢失，旧代码使用可空 let 会静默跳过写入。

0.2.1 改用 LastAudioStore：入口从持久化文件判断可用，导出先解析验证旧版 last.wav，再输出完整 WAV；不依赖 Activity 内存。采集保存使用临时文件、sync 和原子替换，保存失败不覆盖前一段录音。文件选择器在初始化期间返回时延后处理，避免用“忙碌”状态丢弃回调。

同时新增顶部状态栏和模型导入的解压数据量/校验/成功提示；WAV 成功导出显示明确提示，错误不再冒充完成。包名不变、versionCode 3、versionName 0.2.1，沿用同一调试签名，可覆盖安装；不应先卸载，以便保留模型、已有 last.wav 和日志。

JVM 回归验证：旧版格式 last.wav 在重新创建 store 后能按字节导出；新录音原子保存、无效保存保留旧音频、缺文件/损坏文件拒绝及不输出空成功均通过。独立 Python WAV 解码另验证输出参数。Android 完整构建与签名日志在 .evidence/wav-export/。此修复尚需用户在真机更新后复核导出，不能把 JVM 通过当作手机回归通过。

手机导出的原始事件在 .evidence/phone-a/events-before-wav-fix.jsonl。包含 0.896 秒 NO_SPEECH 失败和 17.024 秒本地成功两次记录，成功任务的完整反馈 22399 ms。两条有效输入分类均为 null，未人为改成正式分类；没有据此计算正式完成率或 P90。
