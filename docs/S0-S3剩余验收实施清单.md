## 4. S0：风险预检与最小契约

### 4.1 M0–M5 模块说明、实际分工与交接

这里的“模块”是业务处理环节，不要求每环节对应一个源文件。**M0 和 M5 在手机执行；M1–M4 在 LOCAL 时由手机运行，在 REMOTE 时由电脑运行，MANUAL_MIXED 按任务计划分配。**电脑网页是独立诊断入口，不能当作手机 M0/M5 的替身。电脑的 `server/modules/` 与手机的 `RealModules.kt` 要用同一模型和配置身份。

#### M0：录音或导入，形成统一音频

- **为什么存在、怎样工作**：把麦克风录音或外部 WAV 转为同一格式，给后续四个算法模块一份可复算输入。手机 `capture/InterviewAudioRecorder.kt`、`WavPcmIO.kt` 负责采集与 WAV 编解码，`MainActivity.kt` 负责权限和提交。电脑 `server/modules/audio_io.py` 只校验、读取导入的 WAV，不承担手机录音。
- **输入 → 输出**：麦克风或文件、题目/样本身份 → 16 kHz、单声道、16 位小端 PCM，样本数、原始 WAV 哈希与任务 ID；M1 接收去掉 WAV 文件头的 PCM。无麦克风权限、坏头、采样率/声道/位深不符、0 或超过 60 秒应明确拒绝，不进入伪成功分析。
- **分工与交接**：林、彭共同在两机录音/导入、导出 WAV；林核对任务创建和事件，彭核对 M1 实际接到的 PCM/样本数；刘在电脑用独立解码核对 WAV 头、时长、哈希，再把固定 WAV 用于电脑 M1 与跨端对照。两手机原始导出和电脑解码记录都要保存。
- **验收重点**：两机各录与导入一次；`PCM 字节数=样本数×2`，重复录音不串数据；权限拒绝后仍可导入；损坏输入可见错误。见 S0-T1、S1-T1/T2。

#### M1：VAD，定位有人声的片段

- **为什么存在、怎样工作**：Silero VAD 判断音频中哪些采样区间含人声，避免把纯静音送给识别器；按固定规则保留原始录音上的片段起止位置。手机实现为 `analysis/semantic/RealModules.kt` 的 `vad()`，电脑为 `server/modules/vad.py`；阈值来自模型清单 `vad_threshold`。
- **输入 → 输出**：M0 的 PCM 和采样数 → 升序、无重叠 `segments[]`，每段含 `segment_id/start_sample/end_sample/pcm`。纯静音返回 `NO_SPEECH`。噪声、短停顿、句中断开可能使内容被切碎；不能把边界误差误认成 M2/M3 的问题。
- **分工与交接**：彭维护并记录手机 VAD 输出；林核对任务计划、错误终态和 M1→M2 请求；刘用同一 WAV 检查电脑 VAD 片段和原始采样坐标，制作手机/电脑边界差异表。规则修改时刘与彭同步阈值、窗口与合并方式。
- **验收重点**：真实语音、纯静音、前后停顿、短暂停顿及噪声样本；核对片段没有越界/重叠、PCM 长度正确、两端差异可解释。见 S0-T2、S1-T2、S3-T2。

#### M2：ASR，语音片段转文字

- **为什么存在、怎样工作**：Vosk 将每个 M1 片段的 PCM 转成中文；每次任务创建识别器，按片段顺序拼接文本并保留原始采样坐标。手机在 `RealModules.kt` 的 `asr()`，电脑在 `server/modules/asr.py`。模型文件及版本由两端清单核对。
- **输入 → 输出**：M1 片段列表 → `transcript.full_text` 与逐段 `text/start_sample/end_sample`；有声而无文字返回 `NO_TRANSCRIPT`，缺模型返回 `MODEL_UNAVAILABLE`。M2 的错词、漏词、片段截断可能影响 M3/M4；人工逐字稿只用于评价，不应替换正式链路输出。
- **分工与交接**：彭核对手机识别器加载、资源释放和实际转写；林核对 M2 远程请求/响应与超时；刘维护电脑 Vosk 模块、同输入转写对照和 CER 统计，并用函数级测量验证性能猜测。旧 0.2.0 单机 M2 约 16–20 秒仅是性能线索，不是当前版本结论。
- **验收重点**：两片段与最后片段不丢字、连续任务不串结果、空转写错误明确；按人工逐字稿算 CER，跨端逐段差异可追查。见 S0-T2、S1-T1/T3、S2-T3、S3-T2。

#### M3：回答和要点的语义编码

- **为什么存在、怎样工作**：把 M2 转写按句切开，与参考要点一起经 SentencePiece 分词、MiniLM ONNX 推理，形成 384 维归一化向量。电脑 `server/modules/semantic.py`，手机 `RealModules.kt` 的 `encode()`、`SentencePiece.kt` 与 JNI `cpp/tokenizer.cpp`。当前两端都把换行作为分句边界；M1/M2 造成的断句可让一个完整要点分散在数句中。
- **输入 → 输出**：`transcript` 与带 ID 的参考要点 → 回答句和要点的 `sentence_id/keypoint_id/text/vector`。缺模型、非法维度、空文本/无法形成句子须有明确错误；不得静默换模型或把无效向量交给 M4。
- **分工与交接**：刘负责电脑端分句/编码诊断、校准集试验、token IDs/张量/向量金样例及配置版本；彭同步手机分词、分句、池化和模型配置并给出同输入原始数值；林核对远程 M3 载荷、身份和中转字节。电脑改动在手机同步前只算电脑端改善。
- **验收重点**：相同文本的 token IDs、张量形状、长文本分块、向量长度/范数及两端容差；对实际自然回答重点检查“段边界导致漏判”。见 S0-T2、S2-T3、S3-T2。

#### M4：参考要点匹配及证据选择

- **为什么存在、怎样工作**：对每个要点向量与回答句向量计算相似度，挑最高分句子作证据，再与 `match_threshold` 比较给出 `covered`。电脑为 `server/modules/match.py`，手机为 `RealModules.kt` 的 `match()`。目前阈值 0.8 是候选值，尚未用人工数据冻结。
- **输入 → 输出**：M3 向量和句子 ID → 每要点的 `score/covered/evidence_sentence_id/evidence_text`。向量维度错误或非有限值应拒绝；没有合理证据时不能把高分误认为人工认可。`sa-test.wav` 四项语义上明显覆盖却都被判未覆盖，是已观察到的漏判，须保留原结果。
- **分工与交接**：刘用 S01–S15 校准集定位分句/阈值问题，比较假阳性与假阴性，冻结电脑规则及版本；彭在手机端同步相同规则与阈值并复跑固定样本；林验证两端任务采用同一配置版本、远程结果身份和页面采纳。人工标注人与复核人确认真实 `expected_covered` 和可接受证据。
- **验收重点**：全覆盖、漏项、同义改写、离题、否定及阈值边界；报告 TP/TN/FP/FN、Precision/Recall/F1、证据命中，独立评价只在冻结后运行；手机/电脑同版本分数差与状态差单列。见 S2-T3、S3-T2。

#### M5：保存任务终态并展示反馈

- **为什么存在、怎样工作**：手机协调器将 M2 转写和 M4 逐要点结果保存为同一任务终态，`MobileScreen.kt`/`MainActivity.kt` 展示；绘制完成后记 `FEEDBACK_VISIBLE`。电脑浏览器 `server/desktop/` 只用于电脑诊断，不代表手机反馈时延。
- **输入 → 输出**：当前 task_id/attempt、转写、匹配、节点状态与耗时 → 手机完整反馈、私有任务文件和实验事件。失败/取消/重启中断必须保持对应终态；迟到回包不能改写已取消结果；缺展示回执不能冒充成功反馈时延。
- **分工与交接**：林负责手机协调器、状态/取消/恢复、事件与导出；彭核对反馈所示转写/要点/证据与算法结果一致；刘核对电脑结果及服务响应作为跨端输入，收到两机导出后检查同一任务身份和计时关联，不代替手机页面操作。
- **验收重点**：页面、任务文件和 JSONL 同一 task_id/attempt；两机正常、失败、取消、重启均有可区分结果，`FEEDBACK_VISIBLE` 在真实绘制后记录。见 S1-T1/T3、S2-T2、S3-T1。

**跨模块网关与协议**：刘负责电脑 `server/app.py`、`server/gateway/` 的真实服务启动、鉴权、校验、去重、超时与 M1–M4 注册；林负责手机 `RemoteExecutor.kt`/协调器逐模块调用与客户端字节；彭核对载荷中模型/算法字段和跨端输出。三方用同一固定 WAV 和版本完成 S0-T3、S3-T1/T3/T4，不能把电脑 HTTP 回环当手机联调。

### S0-T1 两机音频入口

- **操作**：林、彭在两台手机分别录约 10 秒中文音频、导入同一固定 WAV、再导出 WAV；另导入损坏头、非 16 kHz、非单声道、非 16 位、超长/超大文件。刘用电脑独立解码工具核对文件头、采样率 16000、1 声道、16 bit、小端 PCM、样本数、`PCM 字节数=样本数×2`、时长和 SHA256；手机端重复录两次以排除旧缓冲串入。
- **通过**：两机导出的有效音频能独立解码且样本数与字节数一致；坏输入得到明确拒绝，未创建伪成功任务。拒绝麦克风权限后导入仍可用。记录真机实际行为，不能以电脑转换的 `sa-test.wav` 代替。
- **证据**：林、彭交 APK/设备信息、原始与导出 WAV、错误界面和日志；刘交独立解码和哈希记录，三方核对同一音频身份。

### S0-T2 模型、分词和跨设备金样例

- **操作**：两机飞行模式导入同一模型 ZIP，检查 SHA256、装载与释放；电脑用同一清单。对固定 PCM 记录 M1 片段边界、M2 转写；对固定文本记录 SentencePiece token IDs、输入张量形状/掩码、384 维向量范数和 M4 分数。另用静音、长文本、重复两次调用与缺/坏权重验证边界。先登记预期输出和容差，再比较实测。
- **通过**：两机和电脑都能使用指定版本；token IDs 和张量结构符合冻结期望，数值满足预注册容差，缺/坏权重明确报错。记录冷/热加载时间与内存现象，不能只写“可运行”。任何差异定位到文件、分词、池化、VAD 或后处理后再锁定。

- **通过**：成功样例通过契约；错误返回可识别且状态码/错误码符合 `contracts/errors.md`；林确认手机解码/路由，彭确认手机 M1–M4 数据，刘确认电脑服务和真实响应；三方登记协议版本及评审结论。

## 5. S1：两机离线语音回答闭环

### S1-T1 正常路径

- **操作**：两机各开启飞行模式，分别做一次真实录音和一次相同固定 WAV 导入；选择 `LOCAL`，输入“如何组织社区反诈宣传”的 3–5 条参考要点，完成 M0→M5。对同一 task_id 检查音频、片段、转写、逐要点覆盖/证据、页面和终态保存。
- **通过**：四次任务均能从手机页面完整提交与展示；M0–M5 的实际执行端均为 LOCAL，任务只产生一个采纳终态。反馈所示文本、证据和保存结果一致；无网络依赖。
- **证据**：林、彭提供两机屏录、导出任务与事件、WAV、模型身份并交叉复跑手机正常路径；刘核对固定输入在电脑的对应输出，三方分别记录实际参与和复核，不以电脑复跑代替真机复跑。

### S1-T2 失败边界

- **操作**：拒绝麦克风权限后导入 WAV；静音触发 `NO_SPEECH`；移除/损坏模型包触发可见的 `MODEL_UNAVAILABLE`；试坏 WAV、音频上限、空要点；观察是否有错误码、提示和错误终态。
- **通过**：失败不出现成功反馈、不留下冒充真实结果的任务；可继续执行下一有效任务。权限拒绝不阻断文件导入。
- **证据**：林、彭交叉复测并提供操作/界面录屏、终态任务文件和事件；刘核对电脑服务的缺模型与错误响应及手机回传的错误身份。

### S1-T3 隔离、取消与恢复

- **操作**：连续提交两条不同回答；运行中取消并等待原生调用返回；运行中结束应用并重开；检查旧 task_id/attempt 的迟到响应、任务状态和新任务可用性。
- **通过**：两条结果不串；取消后旧结果不能刷新页面或改写终态；重启未完成任务标为 INTERRUPTED，不自动变成成功或重复提交；已保存的成功结果保留。
- **证据**：前后任务 ID、页面/文件/JSONL 对照、时序记录。林维护手机协调器证据，彭复核手机反馈和算法输出；刘核对远程迟到结果是否被正确拒绝，不把电脑单测当作手机恢复证据。

**S1 出口**：真实两机离线正常、失败、取消和恢复均通过；交付可安装 APK、固定样本、任务和事件字段说明给 S2。

## 6. S2：真实样本、两机基线与质量

### S2-P1 先建立人工金标准

- 至少 **30 段不同的真实录音**，每段有实际同意记录、稳定 `sample_id`、`topic_id`、原始 WAV 与 SHA256、说话者编号、人工逐字稿、要点清单及逐项 `expected_covered`。标注者与独立复核者分别登记；对“已覆盖”要点标注可接受的证据句，对不确定项先仲裁而非猜测。
- 按 **题目** 分到 `calibration`（校准）和 `evaluation`（独立评价）；同一 `topic_id` 不得跨组。同一段音频重复运行只增加运行观测，不增加独立样本数。要包含完全覆盖、漏要点、离题、自然停顿/口误和不同长度；静音/损坏等预分类无效输入单列。
- `experiments/samples/manifest.template.json` 是格式起点，`check_samples.py` 做结构与哈希检查；审核输入沿用 `quality-review.template.json`。工具通过不证明人员真的复核过。
- 当前 `sa-test.wav` 及其四项漏判可用于校准诊断；不要在看过它后再把它作为独立评价证据。先分清 M2 转写误差、M1 段边界、M3 句边界与 M4 阈值影响，再改代码或配置。改动同时更新电脑和手机实现，冻结新的 `config_version`，重跑受影响的 S0/S1 对照。

### S2-T1 两机单机实验矩阵

- **标准条件**：同一批 10 秒中文音频、3–5 要点、单在途、预热、LOCAL。分别记录两机、录音/导入、冷/热、不同长度（10/30/60 秒）及失败/非标准输入；每一份运行配置固定设备、版本、网络、缓存、充电、电量/温度、样本来源和要点数。变更条件用新的 `run_id`。
- **实施入口**：手机先导出“本机及模型信息 JSON”；用 `experiments.scripts.mobile_experiment prepare` 生成运行配置并导入手机，再导入原始样本清单。按 `docs/experiment-workflow.md` 运行并导出“完整实验记录 ZIP”；用同一工具 `validate` 核对关联。原始录音默认不在 ZIP 中，另保管。
- **数量**：主要配置按计划累计不少于 **100 次预分类有效输入的任务尝试**，失败和取消仍在完成率分母；报告每台设备、每组配置实际尝试数、成功数和缺测数。重复同一音频不算新的独立语义样本。
- **通过**：两机均有标准和非标准观测，导出记录能回溯 APK/模型/样本/配置；实际执行端 LOCAL；记录样本量与任何缺测。目标未达成可形成基线，但相应指标不能标通过。

### S2-T2 计量与人工复算

- 用一份含成功、失败、取消和中断的真实 JSONL，按 `run_id/device_id/task_id` 去重；核对 `TASK_TERMINAL`、`FEEDBACK_VISIBLE`、M0–M5 耗时、实际执行端、流量及缺测。失败/取消/中断计入预分类有效输入的完成率分母；只有成功且有 `FEEDBACK_VISIBLE` 才纳入反馈时延分位数。
- 从原始事件人工复算至少一项完成率、一个 P90 和一个节点耗时，再与 `compute_metrics.py` 输出 CSV/图一致。说明 P50/P90/P99 的成功样本量；导入与录音分别报告，录音作答时间不计入提交到反馈时延。
- 标准负载的组内**预设目标**：反馈 P90≤5 秒、P90−P50≤2 秒、实时率≤0.5、连续吞吐≥6 任务/分钟、有效输入完成率≥99%。这些不是已有结论。能耗没有可靠测量时仅报告代理指标，不宣称节能。

### S2-T3 转写与匹配质量

- 逐条核对人工逐字稿与实际 M2 转写；统计标准评价集中文 CER，目标≤20%。用人工要点标签与实际 M4 判断统计 TP/TN/FP/FN、Precision、Recall、F1、全标注正确率和缺测；核对模型证据句是否在人工接受集合中。`quality_metrics.py` 输出报告和逐样本明细。
- 阈值仅在校准集选取；评价集只用于冻结后的独立报告。刘已观察到的四项漏判应保留为失败样本，查清分句和阈值原因；不能简单降低阈值后只展示这个样本的改善。人工抽查输入、标签、版本与报告行可追溯；评价与校准的 `topic_id` 不重叠。
- 质量指标即使达标，也要列出未达目标、空转写、假阳性、假阴性及证据错误的样本，不用整体平均掩盖设备和题目差异。

**S2 出口**：两机原始事件、至少 30 段审核样本、按题目隔离的评价结果、可复算基线与未达标诊断齐全；给 S3 固定样本和跨端容差，给 S4 原始计量列。未达到预设目标应如实标注待改进。

## 7. S3：两手机与同一电脑的真实跨端联调

### S3-T1 三模式实际归属

- 电脑以 `scripts/Start-Gateway.ps1` 启动真实服务，确认 `/healthz` 的 M1–M4 均可用、`demo=false`、模型/配置版本与手机一致；两手机访问同一电脑 IPv4 和端口，使用临时凭据。
- 对固定 WAV 分别跑 LOCAL、REMOTE、MANUAL_MIXED；M0/M5 必须 LOCAL，混合模式至少有一次真实跨端。记录 M1–M4 每步计划归属与实际执行端、任务/attempt、结果和反馈。三模式在两机都有实测记录。
- 通过标准：实际执行端与冻结计划相同，远程调用完成后中间结果回手机再由协调器提交下一模块；完成/失败均保持同一任务身份。只有电脑 HTTP 回环或 JVM fixture 不足以通过此项。

### S3-T2 同输入逐模块一致性

- 先比较固定片段在手机与电脑的 M2，然后扩大到 M1 片段起止、M2 转写、M3 token IDs/向量、M4 分数、覆盖状态和证据句。记录相同模型/配置版本、原始输入哈希与每步完整输出。跨设备相似度绝对差的组内目标≤0.01；阈值附近即使分数差小也单列状态差。
- 对差异逐层定位 VAD、识别、分词、池化、浮点误差、句子切分或协议序列化；超差样本不得直接标通过。刘汇总电脑/手机差异单并核对服务，彭复跑手机算法，林复跑手机路由与传输。

### S3-T3 协议失败与恢复

- 在**真实服务加手机调用**中覆盖：错凭据、错模型/配置版本、坏 JSON/PCM、超限请求、已知但缺模型模块、同键同内容重发、同键异内容冲突、在途重复、服务超时/不可达及运行中取消。核对 HTTP 状态、错误码、页面提示、任务终态和后续新任务可用性。
- 通过标准：拒绝不写成功结果；重复同键遵循协议缓存与冲突规则；超时或取消的迟到响应不覆盖终态。固定协议样例可先复跑，但最终需要至少一组手机真实路径记录。

### S3-T4 手机中转与字节账

- 选连续两个 REMOTE 节点，逐笔记录前一模块响应回手机的 `bytes_down` 与后一模块由手机再次上传的 `bytes_up`，核对 UTF-8 JSON 正文字节、序列化/反序列化和 HTTP 往返。与电脑网关日志按 task/attempt/module 关联，失败和重试单列。
- 通过标准：不假设电脑模块间直接传递数据；实际字节可从导出的请求/响应与事件独立复算；正文、包头和重传开销的计量范围说清楚，形成 S4 成本输入所需原始列。

**S3 出口**：两机三模式、跨端差异、失败用例、连续远程中转和三方签收齐全；冻结 HTTP v1、APK/服务提交号、模型/配置及计量版本。S4 才可据此建成本表和静态切分实验。
